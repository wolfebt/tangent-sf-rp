## 2025-02-23 - Insecure Invite Code Generation Using Math.random
**Vulnerability:** The invite code generation function (`generateInviteCode`) was using `Math.random()` to generate authorization/invite codes, which is not cryptographically secure and can be guessed by observing the output stream.
**Learning:** `Math.random()` should never be used for anything sensitive like invite codes, session tokens, or cryptographic keys. When fixing this by replacing it with `globalThis.crypto.getRandomValues()` and modulo division (`%`), the character set length was intentionally 32. If a character set has a length that is a power of 2 (like 32), it avoids modulo bias completely when mapping from 256 random values (0-255 from Uint8Array).
**Prevention:** Always use `globalThis.crypto.getRandomValues()` or `window.crypto.getRandomValues()` for sensitive identifiers. If using modulo to map random bytes to string characters, ensure the length of the string character set divides perfectly into 256 (e.g. lengths like 2, 4, 8, 16, 32, 64) or use a modulo bias rejection sampling technique.
